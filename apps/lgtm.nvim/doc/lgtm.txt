*lgtm.txt*  Notes and local/GitHub review through LGTM

SETUP                                                        *lgtm-setup*

Requires Neovim 0.11+, the compatible lgtm CLI and backend, curl, NuiComponents, NUI, CodeDiff with its native library, WhichKey, and nvim-notify. Kak is optional. Git reviews need Git. GitHub reviews need gh auth login as the backend's local user.

Supported lazy.nvim installs need one LGTM declaration. Root lazy.lua supplies dependencies and monorepo runtime setup. Keep package loading and its lazy source enabled. Other managers and disabled package metadata need explicit dependencies. See README.md for exact revisions and examples. Run :checkhealth lgtm for missing modules, executables, or backend capabilities.

The nvim:install-dev-plugin and nvim:install-released-plugin Premise tasks select a checkout root or main while retaining user options. The selected revision must contain root lazy.lua. Restart Neovim after switching.

COMMANDS                                                     *lgtm-commands*

:Lgtm note / notes           Add current-line/range note / inspect current-file notes.
:Lgtm review                 Choose Working, Staged, Branch, or PR.
:Lgtm directory [path]       Includes ignored files and explicit symlink root.
:Lgtm prs [URL]              List current-branch PRs for the Git remote; optional URL override.
:Lgtm sessions [completed]   Resume or inspect local/GitHub sessions.
:Lgtm files / threads        Persistent file pane / all-file conversation pane.
:Lgtm comment [line/file/general]
:Lgtm promote                Confirm note target anchor; keep original note.
:Lgtm export [notes/review]  Markdown preview, file or clipboard; no mutation.
:Lgtm save / complete        Confirm durable draft / complete local session.
:Lgtm sync                   Sync/recover pending PR drafts; never publish.
:Lgtm submit / reconcile     Remote outcome + optional final body / check result.
:Lgtm close                  Close UI without completing the review.

KEYS                                                         *lgtm-keys*

<leader>r                    WhichKey review actions (configurable prefix).
Enter/K                     Open the thread card in a centered modal.
Tab/Shift-Tab in modal      Select next/previous top-level comment or reply.
c/e/dd/x                     Reply/edit/delete/resolve in thread popup.
q/Esc                       Restore source focus/cursor.
]c/[c ]n/[n                 Navigate annotations.
za/zA gH                    Expand cursor/file threads; toggle overlays.
Ctrl-S                      Save composer; failed saves retain text.
f                           Toggle persistent review-file pane.
Enter in file pane          Select file (selected/changed/reviewed marks).
m in tree / <leader>rm      Toggle selected/current file reviewed (✓).
]f/[f Tab/Shift-Tab          Next/previous file or unreviewed file.

Reviewed (seen) marks apply to PR, branch, working-tree, staged and directory
reviews, not notes. Content changes clear marks. Local marks survive editor
restarts. PR marks read and update GitHub's Viewed state.

Comments use full-width status/preview cards. Lost selections show a compact status and preview above the file. The full thread view retains the original range and excerpt. Deleted files retain orphaned
discussions in :Lgtm threads. Staged and branch reviews share local discussions;
PR discussions remain separate.

The modal labels and indents replies, highlights the selected comment, and names the edit/delete target. Deletion asks for confirmation. The threads pane remains open during Enter navigation and x resolution. OUTSIDE DIFF explains unavailable navigation without moving focus. Stale feedback reveals its card above the file.

Set ui.border and ui.highlights in setup options to customize the shared theme.
Default highlight links follow NormalFloat, FloatBorder, Title, Comment, Visual
and DiagnosticInfo/Warn/Error/Ok. See README.md for all Lgtm highlight groups.

Select a comment row before editing/deleting; deletion asks for confirmation.
File/general comments are available in the cross-file thread pane. Confirmed
backend mutations update overlays. PR line/file drafts and replies synchronize
to a private pending GitHub review on save. General comments remain local until
submission. Use :Lgtm sync (<leader>ry) to sync existing local drafts or recover
a lost draft response without reposting it. A lost submit
response must be reconciled before retrying. Notes survive editor/backend
restart. Saved files are required for content-verified non-Git anchors.

Saved-file notes and directory reviews follow recorded moves. BufFilePre/Post
and MiniFiles report renames. Other file managers can emit User LgtmPathRenamed
with data = { from = "/old/path", to = "/new/path" } after moving the file.
Both paths must be absolute; the old path must be absent. Copies do not move
comments. :Lgtm refresh retries a saved move without creating another discussion.

Exports contain numbered Markdown feedback, old-side ~ locations, replies and
final review text. Exporting does not change saved feedback or submit a review.
PR refresh and draft saves follow new base/head commits. A push that races
submission requires a refresh before retrying. Closed or merged PRs keep saved
drafts and history; they cannot accept a new submission.

After submitting, keep the diff open and continue commenting. Saving the next
comment or reply starts a new pending review for the same PR. Published comments
and final text stay published. Reconcile an uncertain submission before starting
another draft.
