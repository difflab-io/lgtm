# Product Requirements Documents

PRDs explain a user problem and define the outcomes and requirements for a proposed product change. They do not replace architecture decisions: use [ADRs](../adr/README.md) for decisions about the technical model and its trade-offs.

Start from [template.md](template.md). Give each PRD a numbered directory (`NNNN-kebab-title/`) with a `README.md` and keep its supporting assets alongside it. Number PRDs sequentially. Keep an idea in `draft` until its scope and acceptance criteria are ready for review.
